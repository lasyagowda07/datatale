# DataTale

### AI-Powered Data Storytelling & Visualization Studio

**Turn raw datasets into meaningful insights, interactive visualizations, and downloadable analytical reports.**

DataTale is a full-stack, AI-assisted data analysis application that transforms CSV datasets into structured statistical summaries, interactive visualizations, and natural-language insights.

It combines deterministic data processing with large language model capabilities to make exploratory data analysis more accessible, interpretable, and actionable.

Rather than relying entirely on AI to interpret raw data, DataTale follows a hybrid approach: **Python calculates the statistics, users confirm how columns should be interpreted, and Claude generates narratives from the resulting evidence.**

**[Live Application](https://datatale-ai.vercel.app)**

---

## Overview

Exploratory data analysis often involves several disconnected steps: inspecting a dataset, identifying column types, calculating statistics, generating charts, investigating anomalies, and summarizing findings.

For users without extensive data analysis experience, this process can be time-consuming and difficult to interpret.

DataTale brings these steps into a single workflow.

Users can upload a CSV file, review its structure, confirm AI-suggested column classifications, explore statistical summaries and visualizations, generate AI-powered insights, and export the analysis as a PDF report.

The application is designed around three principles:

- **Statistical correctness:** Numerical calculations should come from deterministic code rather than language-model estimates.
- **Human oversight:** Users should retain control over how their data is interpreted.
- **Explainability:** AI-generated findings should include supporting evidence, uncertainty, and limitations.

## Features

### 1. CSV Upload and Dataset Profiling

Upload a CSV dataset and receive an immediate overview of its structure.

DataTale automatically identifies:

- Total rows and columns
- Column names and inferred data types
- Missing values per column
- Unique values per column
- Duplicate rows
- A preview of the first five records

CSV files are validated before processing, with a maximum upload size of **10 MB**.

The current application processes uploaded datasets in memory without storing them in a persistent database.

### 2. AI-Assisted Column Classification

One of the central challenges in automated data analysis is determining what each column represents.

A numeric-looking column is not necessarily a meaningful numerical variable.

For example:

- `MortgageAmount` should be analyzed numerically.
- `State` should be treated as categorical.
- `PropertyZip` may contain digits but should not be averaged.
- `LoanID` is an identifier and should generally be excluded from statistical analysis.

DataTale uses **Anthropic Claude** to recommend one of three classifications for each column:

| Classification | Purpose |
|---|---|
| Numeric | Continuous or discrete values suitable for numerical statistics |
| Categorical | Labels, groups, flags, and discrete categories |
| Skip | Identifiers or columns unsuitable for the available statistical analysis |

Each recommendation includes a confidence score.

Classifications below a **0.85 confidence threshold** are flagged for review.

Users can manually adjust classifications before proceeding, ensuring that AI suggestions do not automatically determine the final analysis.

This human-in-the-loop design reduces the risk of misleading statistics caused by incorrectly interpreted columns.

### 3. Deterministic Statistical Analysis

After classifications are confirmed, DataTale calculates descriptive statistics using **Pandas and NumPy**.

For numeric columns, the analysis includes:

- Mean and median
- Minimum and maximum
- Standard deviation
- 25th and 75th percentiles
- Missing and valid value counts
- Histogram distributions
- Box plot statistics and potential outliers

For categorical columns, the analysis includes:

- Unique category counts
- Category frequencies
- Percentage distributions
- Most frequent categories
- Missing and valid value counts

Statistical calculations are performed by Python rather than generated by the language model.

This separation allows the AI layer to focus on interpretation while keeping the underlying numerical analysis reproducible.

### 4. Interactive Data Visualizations

DataTale presents statistical results through interactive charts built with **Recharts**.

Depending on the column type, users can explore:

- Category frequency charts
- Donut charts
- Numeric histograms
- Box plots

The visualizations use statistics calculated by the backend.

This provides a visual representation of distributions, category imbalances, skewness, and potential outliers without requiring users to write visualization code.

### 5. AI Insights and Data Storytelling

DataTale uses Claude to transform calculated statistics into readable analytical narratives.

Instead of sending a dataset to an LLM and asking it to perform calculations, the application first computes structured statistics and then supplies those results to the model.

The generated analysis includes:

- A dataset-level summary
- Key findings
- Interesting patterns and potential anomalies
- Data quality warnings
- Supporting statistical evidence
- Interpretations and important caveats
- Overall analytical limitations

Findings are organized into categories such as warnings, informational observations, and interesting patterns.

The application uses **Pydantic models** to validate the structure of Claude's responses before presenting them to users.

The current implementation validates the response schema but does not independently verify every AI-generated evidence claim against the original dataset. AI interpretations should therefore be reviewed before use in consequential decisions.

### 6. Downloadable PDF Reports

Users can export their analysis as a structured PDF report.

Reports are generated using **ReportLab** and include:

1. Dataset overview
2. Data quality summary
3. Column profiles
4. Confirmed column classifications
5. Numeric statistical analysis
6. Categorical statistical analysis
7. Data visualizations
8. AI-generated insights and supporting evidence
9. Methodology and limitations

PDF charts are rendered separately from the interactive frontend visualizations.

Importantly, **downloading a report does not trigger another Claude API request**.

The frontend passes previously generated insights to the backend, which recalculates deterministic statistics and assembles the report in memory.

This avoids unnecessary API costs and keeps report generation separate from AI inference.

### Frontend

The Next.js frontend manages the user-facing analysis workflow.

Its responsibilities include:

- CSV selection and upload
- Dataset preview and profiling
- Displaying AI-suggested classifications
- Collecting manual classification overrides
- Requesting statistical analysis
- Rendering interactive charts
- Displaying AI-generated insights
- Downloading PDF reports

The frontend communicates with the backend through HTTP API endpoints.

### Backend

FastAPI handles file validation, data processing, AI orchestration, and report generation.

Its responsibilities include:

- Validating uploaded files
- Parsing CSV data
- Calculating dataset profiles
- Requesting AI column classifications
- Validating confirmed classifications
- Calculating deterministic statistics
- Requesting structured AI insights
- Validating AI response schemas
- Generating PDF reports

### AI Layer

Claude is used for two specific tasks:

**Column classification:** Recommend how dataset columns should be interpreted.

**Data storytelling:** Generate natural-language findings from calculated statistics.

Claude is not responsible for calculating numerical statistics or producing chart data.

## Analysis Workflow

The application follows a structured, multi-stage workflow.

```text
1. Upload CSV
       |
       v
2. Validate and Profile Dataset
       |
       v
3. Request AI Column Classifications
       |
       v
4. Review and Confirm Classifications
       |
       v
5. Calculate Deterministic Statistics
       |
       v
6. Generate Interactive Visualizations
       |
       v
7. Generate AI Insights
       |
       v
8. Download PDF Report
```

### Why classification happens before statistical analysis

A column's physical data type does not necessarily describe its analytical meaning.

ZIP codes, identifiers, and binary flags can be represented numerically while requiring different analytical treatment.

By separating classification from statistical analysis, DataTale allows users to correct the interpretation of a column before potentially misleading statistics are calculated.

### Why statistics are calculated before AI insights

Language models are useful for explaining patterns but should not be treated as the source of truth for numerical calculations.

DataTale therefore uses a two-stage approach:

1. Python calculates statistics from the dataset.
2. Claude interprets those statistics and produces structured findings.

This design reduces reliance on model-generated arithmetic and creates a clearer boundary between computation and interpretation.

## Key Engineering Decisions

### 1. Human-in-the-Loop AI Classification

**Decision:** Allow Claude to recommend classifications while giving users final control.

**Reasoning:** Automatic classification can incorrectly interpret identifiers, categorical flags, or domain-specific fields.

A confidence threshold identifies uncertain predictions, while manual overrides let users correct classifications before analysis.

### 2. Deterministic Computation, AI Interpretation

**Decision:** Use Pandas and NumPy for statistical calculations and Claude for interpretation.

**Reasoning:** Numerical correctness should not depend on an LLM's ability to perform arithmetic.

This architecture separates reproducible computation from probabilistic language generation.

### 3. Structured AI Responses

**Decision:** Define expected AI response structures using Pydantic.

**Reasoning:** Unstructured model responses are difficult to integrate reliably into frontend components and reports.

Schema validation provides a predictable interface between the AI layer and the application.

### 4. Avoiding Overly Restrictive Evidence Validation

**Decision:** Retain structural validation while deferring strict automated evidence verification.

**Reasoning:** An initial evidence validator proved too brittle for legitimate categorical evidence formats.

Rather than rejecting otherwise useful analyses, the application retains Pydantic schema validation and makes analytical caveats visible.

Independent evidence verification remains an area for future improvement.

### 5. Stateless, In-Memory Dataset Processing

**Decision:** Process uploaded CSV files in memory rather than introducing a database.

**Reasoning:** The initial product focuses on individual analysis sessions, not long-term dataset management.

Avoiding persistent storage reduces infrastructure complexity and keeps the initial implementation focused on the analysis workflow.

### 6. Reusing AI Insights During Report Generation

**Decision:** Generate insights once and reuse them when exporting the PDF.

**Reasoning:** Making another Claude request during report generation would increase latency, cost, and the possibility of inconsistent narratives.

The report endpoint accepts previously generated insights and recalculates statistics independently.

### 7. Separate Frontend and Backend Deployment

**Decision:** Deploy Next.js on Vercel and FastAPI on Render.

**Reasoning:** Each platform supports the respective application's runtime and deployment model.

The frontend uses an environment-configured API URL, while the backend uses an explicit CORS allowlist to permit requests from the deployed frontend.

This architecture also keeps the Anthropic API key on the backend rather than exposing it to the browser.

## Running Locally

### Prerequisites

- Python 3.12
- Node.js and npm
- An Anthropic API key

### 1. Clone the repository

```bash
git clone <repository-url>
cd Datatale
```

Replace `<repository-url>` with the repository's GitHub clone URL.

### 2. Configure the backend

Create and activate a Python virtual environment:

```bash
python3.12 -m venv venv
source venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create `backend/.env`:

```dotenv
ANTHROPIC_API_KEY=your_anthropic_api_key
ALLOWED_ORIGINS=http://localhost:3000
```

Never commit real API keys to version control.

### 3. Start FastAPI

From the repository root:

```bash
python -m uvicorn backend.main:app --reload --port 8000
```

The backend runs at:

```text
http://localhost:8000
```

Interactive API documentation:

```text
http://localhost:8000/docs
```

### 4. Configure the frontend

Open another terminal:

```bash
cd frontend
npm install
```

Create `frontend/.env.local`:

```dotenv
NEXT_PUBLIC_API_URL=http://localhost:8000
```

### 5. Start Next.js

```bash
npm run dev
```

Open:

```text
http://localhost:3000
```

Upload a CSV dataset to begin analyzing it.

https://datatale-backend.onrender.com

Configuration:

```text
Runtime: Python
Root Directory: Repository root
Build Command: pip install -r requirements.txt
Start Command: uvicorn backend.main:app --host 0.0.0.0 --port $PORT
Health Check: /health
```

Environment variables:

```dotenv
ANTHROPIC_API_KEY=<configured securely in Render>
ALLOWED_ORIGINS=http://localhost:3000,https://datatale-ai.vercel.app
```

The Anthropic API key is configured server-side and is not exposed through a `NEXT_PUBLIC_` environment variable.

**Note:** The backend currently runs on Render's free instance, which may spin down during inactivity. The first request after an idle period can therefore take longer than subsequent requests.

## Current Limitations

DataTale is an exploratory analysis application, not a replacement for domain-specific statistical review.

Current limitations include:

- CSV uploads are limited to 10 MB.
- Datasets are processed in memory and are not persisted.
- The application does not currently provide user accounts or saved analysis histories.
- The available analysis focuses primarily on individual columns rather than cross-column relationships.
- AI-generated findings are schema-validated but are not independently fact-checked against every underlying data point.
- Outlier detection identifies statistical anomalies, not necessarily incorrect records.
- The public AI endpoints do not yet have application-level rate limiting.
- The Render free instance may introduce cold-start delays.

These limitations are intentional boundaries of the current implementation or areas identified for future development.
